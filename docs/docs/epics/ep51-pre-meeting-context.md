## Problem

The calendar widget shows meetings but provides almost no preparation context. Clicking a meeting currently expands a flat `pre_brief` text block generated by keyword FTS against messages. It has four gaps:

1. **No attendee-based lookup** — the brief is built from title keywords, not from actual people in the meeting
2. **No past meeting history** — doesn't show what was decided last time this group met
3. **No action item linkage** — open items assigned in previous meetings with the same attendees are invisible
4. **No Jira linkage** — relevant tickets assigned to attendees aren't surfaced

Additionally, two bugs prevent the calendar from showing today's events at all:
- `CALENDAR_TTL_MS` is referenced but never declared → 500 error on `?days=7`
- `getUpcomingEvents` uses `datetime('now')` (UTC) instead of localtime, causing events to vanish after midnight UTC

## Decisions Made

See [ADR-010](../adr/adr-010-meeting-intelligence) for full rationale. Key decisions:

| # | Decision | Why |
|---|----------|-----|
| D1 | Inline expand panel in `TodaysCalendarSection` (not a new page) | User confirmed: inline is preferred; avoids navigation break |
| D2 | New `GET /api/calendar/events/:id/context` endpoint | Keeps pipeline separation clean; briefs stay in `/regenerate-brief` |
| D3 | Attendee resolution via `member_aliases` table (EP-45) | More accurate than name matching; aliases cover display name + email variants |
| D4 | Context sections are independent DB queries — no AI call on expand | Instant response; AI is only called for pre_brief generation, not context fetch |
| D5 | "Prepare me" button uses `sendToChat()` pattern | Consistent with existing chat injection pattern (chat ticket mention, EP-49-10) |
| D6 | Fix `CALENDAR_TTL_MS` and timezone bug as part of this epic | Can't deliver the panel without fixing the widget that hosts it |

## Code Shapes

### New endpoint registration (web-server.js)

```javascript
// GET /api/calendar/events/:id/context (EP-51-1)
const calendarContextMatch = path.match(/^\/api\/calendar\/events\/(\d+)\/context$/);
if (calendarContextMatch && req.method === 'GET') {
  const eventId = parseInt(calendarContextMatch[1]);
  const event = db.prepare('SELECT * FROM calendar_events WHERE id = ?').get(eventId);
  if (!event) { json(res, 404, { error: 'Event not found' }); return; }
  const context = buildMeetingContext(db, event);
  json(res, 200, context);
  return;
}
```

### `buildMeetingContext()` helper (web-server.js, new function)

```javascript
function buildMeetingContext(db, event) {
  const attendees = parseAttendees(event.attendees); // JSON array of { name, email }

  // Resolve member IDs via aliases
  const memberIds = attendees.flatMap(a => {
    const rows = db.prepare(
      `SELECT DISTINCT ma.member_id FROM member_aliases ma
       WHERE lower(ma.alias) = lower(?) OR lower(ma.alias) LIKE lower(?)`
    ).all(a.name, `%${a.email ?? a.name}%`);
    return rows.map(r => r.member_id);
  });

  // Build FTS query from title keywords
  const keywords = extractKeywords(event.title); // 3+ char words, stop-word filtered
  const ftsQuery = keywords.map(k => `"${k}"`).join(' OR ');

  // Recent messages: by attendee name OR title keywords
  const recentMessages = ftsQuery
    ? db.prepare(`SELECT m.id, m.subject, m.content, m.author, m.source, m.timestamp
                  FROM messages_fts mf JOIN messages m ON mf.rowid = m.id
                  WHERE mf MATCH ? ORDER BY rank LIMIT 10`).all(ftsQuery)
    : [];

  // Past meetings: title OR chat_name similarity
  const pastMeetings = db.prepare(
    `SELECT id, chat_name, title, date, summary, decisions FROM meetings
     WHERE ${attendees.map(() => 'chat_name LIKE ?').join(' OR ')}
     ORDER BY date DESC LIMIT 5`
  ).all(...attendees.map(a => `%${a.name.split(' ')[0]}%`));

  // Open action items: assignee matches attendee names/aliases
  const nameList = attendees.map(a => a.name.toLowerCase());
  const openActionItems = db.prepare(
    `SELECT id, title, assignee, due_date, status FROM action_items
     WHERE status != 'completed'
     ORDER BY CASE WHEN due_date < date('now') THEN 0 ELSE 1 END, due_date ASC NULLS LAST
     LIMIT 10`
  ).all().filter(item =>
    item.assignee && nameList.some(n => item.assignee.toLowerCase().includes(n))
  );

  // Jira tickets: assignee matches
  const jiraTickets = db.prepare(
    `SELECT issue_key, summary, status, assignee FROM jira_issue_cache
     WHERE status != 'Done' ORDER BY updated DESC LIMIT 20`
  ).all().filter(t =>
    t.assignee && nameList.some(n => t.assignee.toLowerCase().includes(n))
  ).slice(0, 8);

  return { attendees, recentMessages, pastMeetings, openActionItems, jiraTickets };
}
```

### SQL: no new DDL (uses existing tables)

This epic adds zero schema migrations. All data comes from:
